# Practical local prototype

Run `powershell -ExecutionPolicy Bypass -File .\start-practical.ps1`, open `http://127.0.0.1:8765/practical`, and pair using the token in the local terminal. Keep both loopback servers running while using the workspace.

The `/practical` app is a working local interface, separate from the published guided simulation. It accepts single-page PDF/PNG/JPEG documents and uses the existing local engine. It adds PDF properties/XMP-presence inspection, readable image EXIF inspection, approved metadata cleanup, output verification, and single-use upload grants.

- Live browser: local synthetic PDFs were selected through both file inputs. An invalid second candidate showed an error while retaining the first, and replacing it with a valid bill restored comparison.
- Narrow viewport: comparison cards reflowed to one column; both previews loaded and measured content width did not exceed the viewport.
- A recipient-requirements notice was subsequently added before protection consent. JavaScript syntax and all 14 state tests passed after that text/control update. The browser was left under user control and was not operated for that update.

The policy is bounded and heuristic. Required name/address and acceptance are user-confirmed, not authenticated. The engine does not infer that a utility bill is always less revealing, nor that fewer detections establish complete privacy. Possible QR contents and uncertain extraction can make a ranking inconclusive.

## Evidence and boundaries

Implementation screenshots were retained locally and are excluded from Git. Reproducible measurements are generated by `scripts/practical_benchmark.py` and written to `practical-benchmarks.json`.

The recorded pipeline does not run an AI model. Two bounded reasoning agents remain a proposed architecture. Upload evidence is obtained from the controlled portal request plus receiver receipt, not arbitrary-site Chrome request observation. AWS/ElevenLabs remain optional and unimplemented.

Receivers validate a short-lived single-use grant, destination, origin, exact file hash and byte count; they stream the body into a hash/count then discard it. Documents are not sent off-device. Input parsing/OCR can use library-managed temporary files which are cleaned by their existing wrappers. Unsupported structures, uncertain redaction boundaries and failed verification block protected output. No full anonymity, signature authenticity or portal acceptance guarantee is made.
